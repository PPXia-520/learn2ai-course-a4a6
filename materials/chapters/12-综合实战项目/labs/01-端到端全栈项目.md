# Lab 12 · 端到端全栈项目交付

## 选题（三选一，或自选同等复杂度）
| 选题 | 核心难点 |
| --- | --- |
| 报价单工具 | 金额计算精度、PDF 导出、状态流转 |
| 团队任务看板 | 多人协作、实时刷新、权限分级 |
| 内容订阅与推送 | 定时任务、消息队列、订阅状态管理 |

## 交付物（缺一不可）
1. 可运行的代码仓库（前端 + 后端）。
2. `README.md`：10 分钟上手（安装、配置、启动、测试、部署）。
3. `docs/requirements.md`：问题陈述、≥10 条用户故事、验收标准、不做清单。
4. `docs/design.md`：架构图、数据模型、接口清单、≥3 份 ADR。
5. `docs/deployment.md`：环境要求、配置项、部署步骤、回滚步骤。
6. 测试：单元 + 集成 + 至少一条 E2E，一份覆盖率报告。
7. 部署：公网可访问地址 + 冒烟测试脚本。
8. `demo/script.md` + 关键界面截图。
9. `notes.md`：复盘三问的回答。

## 功能要求（MVP 底线）
- 完整认证：注册、登录、退出、受保护路由。
- 核心业务闭环：创建 → 查看 → 编辑 → 删除（或对应的业务动作）。
- 列表具备筛选与分页，筛选条件同步到 URL。
- 三种界面状态齐全：加载中、加载失败（可重试）、空状态。
- 权限：用户只能操作自己的数据，管理员可查看全部。
- 数据持久化到真实数据库（不是内存）。

## 质量要求
- TypeScript 严格模式，零 `any`。
- 关键业务函数与接口有成对的成功／失败测试。
- CI 流水线四步串联（typecheck → lint → test → build），主干全绿。
- 容器化，一条命令可起本地全套依赖。
- 错误统一处理，日志含 requestId。

## 迭代计划（4 轮，每轮都要能演示）
| 轮次 | 目标 | 演示内容 |
| --- | --- | --- |
| 1 | 最小闭环 | 登录 → 创建一条记录 → 列表看到它 |
| 2 | 业务完整 | 校验、编辑、删除、金额或状态计算正确 |
| 3 | 质量与体验 | 三态齐全、测试通过、权限正确、CI 全绿 |
| 4 | 交付上线 | 公网访问、文档齐全、演示彩排完成 |

## 验收清单
- [ ] 陌生人按 README 能在 10 分钟内把项目跑起来（附他卡住的地方与你的修复）。
- [ ] MVP 功能全部可用，核心流程有 E2E 覆盖。
- [ ] 权限测试：用 A 的账号访问 B 的数据被拒绝。
- [ ] CI 流水线全绿，附链接或截图。
- [ ] 公网地址可访问，附健康检查输出。
- [ ] 回滚演练完成，记录了命令与耗时。
- [ ] `design.md` 含架构图与三份 ADR。
- [ ] 5 分钟演示脚本已计时彩排；`notes.md` 完成复盘三问。
- [ ] 项目里没有任何硬编码的密钥或密码。

## 加分项
1. 加一个后台管理页：用户与内容管理，含权限分级。
2. 接入消息队列处理一个异步任务（导出、通知、统计）。
3. 做一次性能优化并有前后数据（首屏体积、接口耗时、慢查询）。
4. 邀请一位同学做代码评审，附评审意见与你的处理记录。
