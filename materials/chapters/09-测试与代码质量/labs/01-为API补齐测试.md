# Lab 09 · 为 REST API 补齐测试

## 目标
给第 06／08 章完成的 REST API 补齐三层测试，并接入 CI 质量门槛。

## 任务一 · 测试策略表
先写一份 `test-plan.md`，逐条说明「测什么、在哪一层测、为什么」：

| 被测对象 | 层级 | 理由 | 优先级 |
| --- | --- | --- | --- |
| 折扣／权限判定逻辑 | 单元 | 纯逻辑、分支多 | 高 |
| 接口校验与状态码 | 集成 | 契约容易改坏 | 高 |
| 登录 → 创建 → 查看 | E2E | 核心用户路径 | 中 |
| 按钮样式 | 不测 | 无逻辑 | — |

要求：至少 12 行，且必须包含 2 行「不测 + 理由」。

## 任务二 · 单元测试
1. 为业务规则函数写测试：金额／权限／状态流转任选。
2. 每个函数至少 5 个用例，必须包含边界（0、空、刚好相等、超限）与异常路径。
3. 用假时钟测试时间相关逻辑，不允许依赖真实时间。

## 任务三 · 集成测试
1. 用独立测试库（库名必须含 `_test`，启动时校验）。
2. 覆盖「成功 + 失败」成对用例：
   - 创建：201／422（缺字段）
   - 查询详情：200／404
   - 更新：200／403（改他人资源）
   - 删除：204／404
   - 冲突：409
3. 实现数据隔离：事务回滚或独立 schema，并验证用例可乱序执行（用 `--sequence.shuffle` 跑一遍）。

## 任务四 · E2E 测试
1. 用 Playwright 写一条主流程：登录 → 创建 → 编辑 → 删除。
2. 全程禁止 `waitForTimeout`，只用自动重试断言。
3. 失败时保留截图与 trace。

## 任务五 · 质量门槛
1. 配置 ESLint（`no-explicit-any` 为 error）与 Prettier，接上提交钩子。
2. 写 CI 流水线：`npm ci` → typecheck → lint → test → build，前一步失败即终止。
3. 记录一次「故意让 lint 失败被 CI 拦住」的证据。

## 任务六 · 抖动治理
1. 故意写一个用固定等待的 E2E，观察它在慢机器上失败。
2. 改成显式等待并验证稳定通过（连续跑 5 次全绿）。
3. 在 `notes.md` 记录抖动原因与修复方式。

## 验收清单
- [ ] `test-plan.md` 含「不测」条目与理由，覆盖三类层级。
- [ ] 单元测试含边界与异常用例，且用了假时钟。
- [ ] 每个集成用例都能单独运行，乱序执行仍全绿。
- [ ] 测试库与开发库分离，且启动时有库名校验。
- [ ] E2E 无固定等待，连续 5 次运行稳定。
- [ ] CI 流水线四步串联，附一次被拦下的记录。
- [ ] 覆盖率报告已产出，并说明未覆盖的分支为什么可以不覆盖。

## 加分项
1. 用 Testcontainers 起临时数据库，做到「本机零配置跑集成测试」。
2. 加入变异测试（mutation testing），看测试能否发现被人为注入的 bug。
3. 给 CI 加缓存与并行，把流水线时间缩短 30% 以上并给出数据。
