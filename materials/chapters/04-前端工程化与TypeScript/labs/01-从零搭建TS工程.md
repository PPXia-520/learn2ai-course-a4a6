# Lab 04 · 从零搭建一个 TypeScript 工程

## 目标
手写配置而不是用脚手架，做出一套「能开发、能构建、能检查、能测试」的最小工程，彻底搞懂每个配置文件的作用。

## 硬性约束
- 不使用 `npm create vite` 之类的脚手架，`package.json`、`tsconfig.json`、`vite.config.ts` 全部手写。
- 全项目零 `any`，开启 `strict` 与 `noUncheckedIndexedAccess`。
- 至少有一个模块使用泛型，至少使用两次工具类型。
- 提交 `.env.example`，并且 `.env*` 已被 `.gitignore` 忽略。

## 目录结构（目标）
```text
ts-starter/
  src/
    main.ts
    core/
      result.ts        # Result<T> 判别联合类型
      group-by.ts      # 泛型 groupBy
    features/
      user.ts          # User 类型、PublicUser、UserPatch
    env.ts             # 环境变量读取与校验
  public/
  tests/
    group-by.test.ts
  .env.example
  .env.development
  index.html
  package.json
  tsconfig.json
  vite.config.ts
  .gitignore
  README.md
```

## 分步实现
1. **初始化**：`npm init -y`，`npm i -D typescript vite vitest`。手工建立上面的目录结构。
2. **写 `tsconfig.json`**：开启 `strict`、`noUncheckedIndexedAccess`、`paths` 别名，`noEmit` 为 true（构建交给 Vite）。
3. **写 `vite.config.ts`**：配 `resolve.alias`、`server.proxy`（指向一个 mock 后端）、`build.manualChunks`。
4. **写类型模块**：`Result<T>` 判别联合 + `User` 系列类型；`groupBy` 用泛型并保证返回类型准确。
5. **写 `env.ts`**：读取 `import.meta.env`，缺失必填变量时抛错并给出清晰提示。
6. **加脚本**：`dev` / `build` / `preview` / `typecheck` / `test` / `lint`。
7. **写测试**：为 `groupBy` 写至少 4 个用例，含空数组与重复键。
8. **验证产物**：`npm run build` 后用 `npm run preview` 打开，确认页面正常、资源路径正确。

## 验收清单

- [ ] `npm run typecheck` 与 `npm run build` 均通过。

- [ ] 页面能读到 `VITE_APP_TITLE`，缺失时给出明确报错。
- [ ] `@/` 别名在源码与测试中都能正确解析。
- [ ] 构建产物含至少两个 chunk（业务 + vendor），并记录各自体积。
- [ ] README 中含「开发/构建」两条命令，新人照做即可跑起来。
