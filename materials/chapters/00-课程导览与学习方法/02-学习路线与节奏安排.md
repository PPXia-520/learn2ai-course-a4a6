## 二、每周节奏模板

| 时间 | 做什么 | 说明 |
| --- | --- | --- |
| 周一晚 | 读本章 README + 看图 + 列疑问 | 30–60 分钟，只做规划不写代码 |
| 周二至周四 | 每天 1 个 90 分钟循环精读讲义 + 敲示例 | 示例必须自己敲一遍，不许复制 |
| 周五晚 | 开始 lab，遇到问题记录到错题本 | 允许卡住，但要写清卡在哪一步 |
| 周六 | 集中攻 lab（2–3 小时） | 专门用来解决卡点 |
| 周日 | 复盘：整理笔记 + 学习日志 + 定下周目标 | 30 分钟 |

**保底原则**：某周只剩 2 小时，优先做「lab 的一小步 + 复盘」，不要用来看新视频。

## 三、单次 90 分钟学习循环

1. **预热（10 min）**：不看资料，凭记忆写下上次学到的 3 个要点，再对照检查。
2. **精读（30 min）**：读一节讲义，边读边标注「这里我不确定」。
3. **动手（30 min）**：把讲义代码敲一遍，然后**故意改坏一处**看报错长什么样。
4. **收尾（20 min）**：写 3 行笔记——学到了什么、哪里还不懂、下次从哪继续。

> 第 3 步的「故意改坏」提效最明显：它把「照着抄能跑」变成「知道为什么能跑」。

## 四、笔记体系：三个文件就够

| 文件 | 记什么 | 写法 |
| --- | --- | --- |
| `concepts.md` | 概念卡片 | 术语 + 我的一句话解释 + 一个例子 + 出处链接 |
| `snippets/` | 可复用代码 | 文件名即用途，如 `debounce.ts`，顶部注释写适用场景 |
| `errors.md` | 错题本 | 报错原文 → 根本原因 → 修复方式 → 同类问题识别特征 |

**规则**：笔记里禁止出现「大概」「应该是」。不确定就写「待验证」，然后去验证。

## 五、卡住时怎么办：四步法

1. **读报错**：先看第一行的错误类型和最后一行的触发位置，不要只盯着中间那句红字。
2. **最小可复现**：新建空文件，只保留出问题的那几行代码，确认问题是否仍存在。
3. **查文档**：MDN／官方文档优先，其次搜社区答案，注意版本差异。
4. **写下来再问**：把「期望／实际／试过什么／怀疑什么」写成四行，大部分问题在写的过程中就被自己解决了。

**向 AI 提问的模板**：

```
环境：Node 20 / Chrome 最新 / Windows 11
期望：点击按钮后列表新增一项
实际：控制台报错 TypeError: xxx is not a function
相关代码：（最小可复现片段，不超过 30 行）
我已尝试：检查函数名拼写、确认 import 路径
我怀疑：这个 ref 在首次渲染时还是 undefined
```

## 六、复习机制：1-3-7-21

| 间隔 | 动作 |
| --- | --- |
| 当天 | 写 3 行笔记 |
| 第 3 天 | 凭记忆默画本章架构图／流程图 |
| 第 7 天 | 合上讲义，重写一个关键示例 |
| 第 21 天 | 重做本章 lab 核心步骤，看能否独立完成 |

每章结束再补一条：**把「我能不能给别人讲明白这一章」当作最终验收**。

## 七、常见失败模式与对策

| 失败模式 | 表现 | 对策 |
| --- | --- | --- |
| 教程依赖 | 不跟教程就写不出东西 | 每学完一节，关掉教程凭记忆重写 |
| 收藏夹式学习 | 存了 200 篇文章，一篇没读完 | 只保留 3 个在学资源 |
| 环境地狱 | 三天都在装工具 | 按第 01 章清单一次装好，遇错记录后跳过 |
| 完美主义重构 | 第 05 章还在美化第 02 章的页面 | 设「够用即走」标准，功能通了就前进 |
| 只学不输出 | 从不写日志、不做项目 | 每周必须提交一次可运行代码 |
| 单打独斗 | 卡住两周也不求助 | 写好四行提问模板，48 小时内发出去 |
