# Lab 11 · 短链系统架构设计

## 目标
为一个「短链接服务」写一份可评审的系统设计文档。这是本章唯一的产出物，也是面试中最高频的题目之一。

## 需求
**功能需求**
1. 用户提交长链接，得到短链接（如 `sn.cn/aB3xK9`）。
2. 访问短链接时 302 跳转到原始链接。
3. 支持自定义短码（可选，需查重）。
4. 支持设置过期时间。
5. 提供该短链的访问统计（总点击、按天趋势、来源分布）。

**非功能需求（由你自己补全并写明假设）**
- 读写比例、峰值 QPS、延迟目标、可用性目标、数据保留时长。

## 任务一 · 需求澄清与估算
产出一张估算表，含：日活跃用户、人均创建数、人均访问数、平均 QPS、峰值 QPS、存储增量（5 年）、带宽。每个数字都要写出假设与推导过程。

参考起点（你可以改）：日新增 100 万条短链，读写比 1 : 100。

## 任务二 · 接口设计
| 方法 | 路径 | 用途 | 成功码 |
| --- | --- | --- | --- |
| POST | `/api/v1/links` | 创建短链 | 201 |
| GET | `/:code` | 跳转 | 302 |
| GET | `/api/v1/links/:code/stats` | 统计 | 200 |
| DELETE | `/api/v1/links/:code` | 删除 | 204 |

要求：写出请求与响应示例、错误码（短码冲突、已过期、不存在）、幂等策略。

## 任务三 · 短码生成方案对比
至少对比三种方案，并给出你的选择与理由：

| 方案 | 原理 | 优点 | 缺点 |
| --- | --- | --- | --- |
| 自增 ID + Base62 | 唯一、无冲突 | 可预测（安全风险） | |
| 随机 Base62 | 不可预测 | 需查重 | |
| 哈希截断 | 无状态 | 有碰撞风险 | |
| 预生成号段 | 高性能 | 需管理号段 | |

必须说明：如何避免碰撞？并发下如何保证唯一？是否需要发号器服务？

## 任务四 · 架构设计
1. 画出架构图（必须有：网关、应用实例、缓存、数据库、队列、统计存储）。
2. 说明跳转请求的完整路径与延迟预算（每一跳的耗时估算）。
3. 说明为什么跳转要用 302 而不是 301。
4. 说明缓存策略：缓存什么 key、TTL 多长、如何避免缓存穿透（不存在的短码）。
5. 说明点击统计为什么必须异步：写入量与写放大如何处理（如按分钟聚合）。

## 任务五 · 取舍与风险
1. 列出**三处明确取舍**，每处写「选了 A，放弃了 B，理由是 C，代价是 D」。
2. 列出**五个单点与失败场景**，每个给出降级或缓解方案。
3. 说明「哪里会先崩」，以及你的扩容顺序。

## 任务六 · 数据模型
给出建表语句或表结构说明，含：短码唯一索引、原链接、创建者、过期时间、状态。说明主键选择与分片键（若需要）。
