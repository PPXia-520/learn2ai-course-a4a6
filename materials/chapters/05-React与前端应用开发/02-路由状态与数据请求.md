# 02 · 路由、状态与数据请求

## 一、路由：把 URL 变成应用状态

单页应用只有一个 HTML，路由负责把 URL 映射到要渲染的组件树。

```jsx
import { createBrowserRouter, RouterProvider } from 'react-router-dom';

const router = createBrowserRouter([
  { path: '/', element: <Layout />, children: [
    { index: true, element: <Home /> },
    { path: 'todos', element: <TodoList /> },
    { path: 'todos/:id', element: <TodoDetail /> },      // 动态参数
    { path: '*', element: <NotFound /> },                 // 404 兜底
  ]},
]);

function App() { return <RouterProvider router={router} />; }
```

| 需求 | 做法 |
| --- | --- |
| 读取动态参数 | `const { id } = useParams()` |
| 读取查询串 | `const [sp, setSp] = useSearchParams()` |
| 编程式跳转 | `const nav = useNavigate(); nav('/todos')` |
| 布局嵌套 | 父路由渲染 `<Outlet />` 作为子路由占位 |
| 路由级懒加载 | `lazy: () => import('./pages/Admin')` |

**筛选条件放 URL**：让「未完成＋第 2 页」这种状态可以被分享与刷新保留，比放在内存里可靠得多。

## 二、状态分类：先分清楚再选工具

| 状态类型 | 例子 | 推荐方案 |
| --- | --- | --- |
| 局部 UI 状态 | 弹窗开关、输入框内容 | `useState` |
| 跨组件共享状态 | 登录用户、主题、购物车 | 提升到公共祖先，或轻量状态库（如 Zustand） |
| 服务端状态 | 列表数据、详情数据 | 数据请求库（如 TanStack Query） |
| URL 状态 | 筛选、分页、标签页 | 路由参数 |
| 表单状态 | 多字段校验 | 表单库或 `useReducer` |

**关键认知**：服务端状态不是你「拥有」的数据，它有缓存、会过期、可能被他人修改，所以要用专门的库管理，而不是塞进全局 store。

## 三、数据请求：加载态、错误态、空态一个都不能少

```jsx
function TodoList() {
  const [state, setState] = useState({ status: 'idle', data: [], error: null });

  useEffect(() => {
    const controller = new AbortController();
    setState({ status: 'loading', data: [], error: null });
    fetch('/api/todos', { signal: controller.signal })
      .then(res => { if (!res.ok) throw new Error(`HTTP ${res.status}`); return res.json(); })
      .then(data => setState({ status: 'success', data, error: null }))
      .catch(err => {
        if (err.name !== 'AbortError') setState({ status: 'error', data: [], error: err });
      });
    return () => controller.abort();
  }, []);

  if (state.status === 'loading') return <Spinner />;
  if (state.status === 'error') return <ErrorBox message={state.error.message} onRetry={reload} />;
  if (state.data.length === 0) return <EmptyState hint="还没有任务，先添加一个吧" />;
  return <ul>{state.data.map(t => <li key={t.id}>{t.title}</li>)}</ul>;
}
```

用请求库后，这些状态被统一成 `isPending` / `isError` / `data`，并自动获得缓存、去重、失效重取：

```jsx
const { data, isPending, isError, error } = useQuery({
  queryKey: ['todos', { status: filter }],
  queryFn: () => api.getTodos({ status: filter }),
  staleTime: 30_000,
});

const mutation = useMutation({
  mutationFn: api.addTodo,
  onSuccess: () => queryClient.invalidateQueries({ queryKey: ['todos'] }),  // 写后失效，自动重取
});
```

| 概念 | 含义 | 实践建议 |
| --- | --- | --- |
| `queryKey` | 缓存的唯一标识 | 把筛选条件放进 key，天然按条件缓存 |
| `staleTime` | 多久内视为新鲜 | 变化不频繁的数据设大一些 |
| 失效重取 | 写操作后让相关查询过期 | 用 `invalidateQueries` 而不是手动改缓存 |
| 乐观更新 | 先改界面再等请求 | 失败时回滚，交互手感更好 |

## 四、表单处理

```jsx
const [values, setValues] = useState({ email: '', message: '' });
const [errors, setErrors] = useState({});

function validate(v) {
  const e = {};
  if (!v.email.includes('@')) e.email = '请输入有效邮箱';
  if (v.message.trim().length < 5) e.message = '留言至少 5 个字';
  return e;
}

function handleSubmit(event) {
  event.preventDefault();
  const e = validate(values);
  setErrors(e);
  if (Object.keys(e).length > 0) return;
  submit(values);
}
```

要点：**受控组件**（值来自状态）便于校验与联动；提交前统一校验；错误信息与输入框用无障碍属性关联（见第 02 章）。

## 五、常见坑

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 请求重复发送 | 依赖数组不稳定或 StrictMode 双调用 | 稳定 key，或用请求库去重 |
| 切换页面后数据串了 | 旧请求后返回覆盖新数据 | 取消请求或按 key 隔离缓存 |
| 刷新后页面 404 | 服务器未配置 SPA 回退 | 部署时把所有路径回退到 `index.html` |
| 列表筛选后仍显示旧数据 | 缓存 key 未包含筛选条件 | 把条件放进 `queryKey` |
| 表单提交两次 | 未阻止默认行为或未禁用按钮 | `preventDefault` + 提交中禁用 |
