# Lab 06 · 构建一个 REST API

## 目标
从零写一个「任务管理」后端服务，接口设计符合 REST 约定，分层清晰、校验完整、错误统一、日志可查。

## 资源与接口
| 方法与路径 | 语义 | 成功码 |
| --- | --- | --- |
| `GET /health` | 健康检查 | 200 |
| `GET /api/v1/tasks` | 列表（支持 `status`、`q`、`limit`、`cursor`） | 200 |
| `GET /api/v1/tasks/:id` | 详情 | 200 |
| `POST /api/v1/tasks` | 创建 | 201 + `Location` |
| `PATCH /api/v1/tasks/:id` | 部分更新 | 200 |
| `DELETE /api/v1/tasks/:id` | 删除 | 204 |
| `POST /api/v1/tasks/:id/complete` | 标记完成（动作型） | 200 |

## 硬性要求
1. **分层**：`routes` 只做解析与响应；业务在 `service`；数据访问在 `repository`（本章可先用内存数组，第 07 章换成真实数据库）。
2. **校验**：所有入参用 schema 校验，失败返回 422 与字段级 `details`（参照 422 结构）。
3. **错误**：`AppError` + 统一错误处理中间件；404、409、422 各至少有一个真实触发路径。
4. **日志**：每个响应输出 requestId、方法、路径、状态码、耗时；错误日志带堆栈。
5. **语义正确**：创建返回 201 与 `Location` 头；删除返回 204 且无响应体；`complete` 重复调用不报错（幂等）。
6. **分页**：使用游标分页，响应含 `pageInfo.nextCursor` 与 `hasMore`。
7. **优雅关闭**：`SIGINT` 时停收新请求、等待在途请求、10 秒兜底退出。

## 分步实现
1. 初始化工程（可复用第 04 章的 `ts-starter`），加脚本 `dev`／`start`。
2. 写 `AppError`、`logger`、`validate` 中间件。
3. 写 task 模块的类型、schema（创建与更新各一份）。
4. 实现 repository（内存版）与 service，注意 409 冲突与 404 不存在。
5. 写路由，注意状态码与 `Location`。
6. 加请求日志与统一错误处理中间件，确认中间件顺序正确。
7. 加 `/health` 与优雅关闭。
8. 用 `curl.exe` 或 HTTP 客户端文件把所有接口跑一遍，保存实际请求与响应。

## 验收清单
- [ ] 七个接口全部可用，状态码与上表一致（用 `curl.exe -i` 记录响应头）。
- [ ] 创建时缺少必填字段返回 422，`details` 能指出字段名。
- [ ] 访问不存在的 id 返回 404，重复创建同名任务返回 409。
- [ ] 删除后再查返回 404，删除响应体为空。
- [ ] 连续两次调用 `complete` 都是 200，任务状态只变一次。
- [ ] 每条日志都有 requestId，同一次请求的多条日志可串联。
- [ ] 服务端没有任何 `res.status(500)` 散落在业务代码中。
- [ ] `Ctrl+C` 后日志显示：停止接收 → 等待在途请求 → 退出。

## 加分项
1. 用 OpenAPI 文件描述全部接口，并用工具生成文档页面。
2. 加限流中间件（按 IP，60 秒 100 次），超限返回 429 与 `Retry-After`。
3. 支持 `Idempotency-Key` 头部：相同键的重复创建只生效一次。
4. 加 `x-request-id` 透传：客户端传入则沿用，否则服务端生成。
