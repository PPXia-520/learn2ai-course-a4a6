# Lab 08 · 安全登录与权限控制

## 目标
在 Lab 06 的 REST API 上加入完整的认证与授权，并交付一份 OWASP Top 10 自查报告。

## 任务一 · 用户与密码
1. 建 `users` 表：`email`（唯一）、`password_hash`、`role`、`created_at`。
2. 实现 `POST /api/v1/auth/register`：邮箱格式校验、密码强度校验（≥8 位且含字母与数字）。
3. 用 bcrypt（cost ≥ 10）存哈希；确认数据库里看不到明文。
4. 登录失败信息统一为「邮箱或密码错误」，不区分具体原因。

## 任务二 · 登录与会话
1. 实现 `POST /api/v1/auth/login`，签发 access token（15 分钟）与 refresh token（7 天）。
2. 实现 `POST /api/v1/auth/refresh`：refresh 轮换，旧 refresh 用后立即失效。
3. 实现 `POST /api/v1/auth/logout`：服务端撤销 refresh，后续刷新失败。
4. 实现 `authenticate` 中间件：无令牌 / 过期 / 伪造分别返回 401 与不同错误码。
5. 给登录接口加限流：同一 IP 每分钟最多 5 次，超出返回 429。

## 任务三 · 授权
1. 任务资源归属于创建者。列表接口返回自己的任务，管理员可看全部。
2. 实现 `requireRole('admin')` 中间件，并给「删除任意任务」接口使用。
3. 每个按 id 操作的接口都要校验归属：
   - 非本人且非管理员 → 返回 403 或 404（说明你的选择理由）。
4. 返回体显式挑选字段：任何接口都不得返回 `password_hash`。

## 任务四 · 攻击复现与修复（重点）
对每一项都要有「复现截图或请求记录 → 修复 → 修复后验证」三段证据：

| 编号 | 攻击 | 复现方式 | 修复要求 |
| --- | --- | --- | --- |
| 1 | SQL 注入 | 用 `' or 1=1 --` 尝试绕过登录 | 参数化查询 |
| 2 | 水平越权 | 用 A 的令牌访问 B 的任务 | 服务端归属校验 |
| 3 | XSS | 任务标题写 `<img src=x onerror=alert(1)>` | 前端 `textContent` / 服务端转义 |
| 4 | 敏感信息泄露 | 查看接口返回体是否含哈希 | 显式 select |
| 5 | 暴力破解 | 脚本连续请求登录接口 | 限流 + 失败计数 |

## 任务五 · 安全自查报告
产出一份 `security-report.md`，按 OWASP Top 10 的十项逐一填写：

| 项目 | 现状 | 风险等级 | 已采取的措施 | 未完成的改进 |
| --- | --- | --- | --- | --- |

要求：十项全部填写；至少三项标注「本轮未覆盖」并说明原因与后续计划。

## 验收清单
- [ ] 注册后数据库中的密码是 bcrypt 哈希，且 cost 参数被记录。
- [ ] 无令牌访问受保护接口返回 401；权限不足返回 403；两者错误码不同。
- [ ] 过期令牌返回明确的 `TOKEN_EXPIRED`，前端可据此触发刷新。
- [ ] 用旧 refresh token 换取新令牌会失败（轮换生效）。
- [ ] 五项攻击全部有复现与修复证据。
- [ ] 任何接口的响应体都不含 `password_hash`。
- [ ] `security-report.md` 十项齐全，含风险等级与改进计划。
- [ ] 服务端日志中不出现密码、令牌原文。

## 加分项
1. 实现「记住我」：长期 refresh（30 天）与短会话两种策略。
2. 加登录失败 5 次锁定 15 分钟，并记录锁定事件日志。
3. 接入 `helmet` 并配置 CSP，用浏览器安全面板验证响应头。
4. 实现基于权限位的文档共享（owner / editor / viewer 三级）。
