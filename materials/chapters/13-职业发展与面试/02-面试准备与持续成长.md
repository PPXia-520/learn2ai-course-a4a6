# 02 · 面试准备与持续成长

## 一、面试的四类问题

| 类型 | 占比（校招／社招参考） | 考察什么 | 准备方式 |
| --- | --- | --- | --- |
| 项目深挖 | 40% / 50% | 你是否真的做过、能否讲清取舍 | 每个项目准备 10 个追问的答案 |
| 基础原理 | 30% / 25% | 语言、网络、数据库、浏览器的理解深度 | 按第 03、06、07 章复习并自测 |
| 场景设计 | 20% / 20% | 能否在没有标准答案时做取舍 | 用第 11 章的方法练习 5 道题 |
| 行为与协作 | 10% / 5% | 沟通、责任心、冲突处理 | 用 STAR 准备 5 个故事 |

## 二、项目深挖：必被问到的 10 个问题

1. 这个项目解决了什么问题？用户是谁？
2. 为什么选这个技术栈？换了会怎样？
3. 最难的一个 bug 是什么？怎么定位的？
4. 接口为什么这么设计？有考虑过别的方式吗？
5. 数据量涨 100 倍，哪里会先崩？怎么改？
6. 你怎么保证正确性？测了什么？
7. 有没有做过性能优化？数据是多少？
8. 上线后出过什么问题？怎么处理的？
9. 如果重做，你会改什么？
10. 项目的哪部分是你独立完成的？

**准备方法**：把答案写成 3 句话的提纲，录一次音计时，控制在 90 秒内讲完一题。

## 三、基础原理：高频清单（自测用）

| 主题 | 必须能答的问题 |
| --- | --- |
| JavaScript | 闭包是什么？事件循环中微任务与宏任务的顺序？原型链查找过程？ |
| TypeScript | 泛型的作用？`unknown` 与 `any` 的区别？判别联合怎么用？ |
| 浏览器 | 从输入 URL 到页面显示发生了什么？重排与重绘的区别？ |
| HTTP | 状态码分类？GET 与 POST 的区别？缓存头怎么用？HTTPS 握手做了什么？ |
| 网络 | 跨域是什么？CORS 预检请求何时触发？CDN 原理？ |
| 数据库 | 索引原理与代价？事务隔离级别？什么情况索引会失效？ |
| 缓存 | 缓存穿透、击穿、雪崩分别是什么？怎么防？ |
| 安全 | XSS 与 CSRF 的区别与防御？越权怎么防？ |
| 工程 | 构建工具做了什么？CI 流水线包含哪些阶段？ |
| 系统设计 | CAP 怎么取舍？如何做限流与熔断？幂等怎么实现？ |

**复习方法**：每一条都先口头讲一遍，再对照讲义修正。**能讲出来才算会**。

## 四、场景设计题：答题框架

```text
1. 澄清需求（30 秒）
   「我先确认几点：日活量级？读写比例？能接受最终一致吗？」
2. 估算量级（30 秒）
   「假设日活 100 万、人均 20 次请求，平均 QPS 约 230，峰值按 5 倍算约 1200。」
3. 给出总体方案（2 分钟）
   「网关 + 无状态应用 + 缓存 + 数据库读写分离 + 队列处理异步任务。」
4. 深入关键点（3 分钟）
   「短码生成用号段 + Base62，跳转走缓存，未命中回源并回填，空值也缓存防穿透。」
5. 主动说取舍与风险（1 分钟）
   「这样做的代价是缓存与数据库可能短暂不一致，我们接受 5 分钟的偏差。」
```

**加分点**：主动提「哪里会先崩」「怎么降级」「怎么监控」。这些体现的是工程成熟度。

## 五、行为面试：准备 5 个故事

| 故事主题 | 面试官想验证 |
| --- | --- |
| 一次技术难题的攻克 | 解决问题的韧性 |
| 一次与他人的分歧 | 沟通与共识能力 |
| 一次失败或事故 | 责任心与复盘能力 |
| 一次主动改进 | 主动性 |
| 一次紧迫期限下的取舍 | 优先级判断 |

每个故事用 STAR 写 200 字，准备三个版本：30 秒、90 秒、3 分钟。

## 六、反问环节：问什么显得专业

| 好问题 | 体现 |
| --- | --- |
| 团队目前最大的技术挑战是什么？ | 关注真实问题 |
| 代码评审与发布的流程是怎样的？ | 关注工程规范 |
| 新人的前三个月期待是什么？ | 关注成长与目标 |
| 这个岗位的绩效怎么衡量？ | 关注结果 |

**不要问**：加班多不多（可换个问法：「团队的交付节奏一般是怎样的」）、能不能远程（除非 JD 提到）。

## 七、持续成长：建立机制而不是靠意志

| 机制 | 做法 | 频率 |
| --- | --- | --- |
| 学习日志 | 每周写一条：学了什么、卡在哪、下一步 | 每周 |
| 输出驱动 | 每月写一篇技术笔记或做一次分享 | 每月 |
| 代码阅读 | 读一个开源项目的关键模块并写笔记 | 每月 |
| 复盘习惯 | 每个项目结束做复盘三问 | 每项目 |
| 能力盘点 | 按第 00 章的四象限自评一次 | 每季度 |

**成长阶段的跃迁点**：

| 阶段 | 关键跃迁 |
| --- | --- |
| 入门 → 独立 | 从「跟着教程」到「自己查文档解决问题」 |
| 独立 → 设计 | 从「实现需求」到「判断该怎么实现」 |
| 设计 → 影响 | 从「做好自己的事」到「让别人也做得更好」 |

## 八、常见坑

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 面试被问倒就慌 | 没有准备「不会时怎么答」 | 诚实说明边界，并给出你会如何查证 |
| 项目讲成技术清单 | 只讲用了什么 | 改讲问题、取舍与结果 |
| 算法题刷了几百道仍挂 | 基础与项目讲不清 | 平衡时间，项目深挖权重大 |
| 学了很多但不输出 | 缺输出机制 | 定每月一篇的机制并公开承诺 |
| 拿到 offer 就停止学习 | 没有长期机制 | 保持学习日志与季度盘点 |

## 九、动手练习

1. 为你的主项目准备 10 个追问的答案，每个 3 句话。
2. 从基础清单里挑 10 个问题，口头回答并录音自查。
3. 用五步框架做一道场景设计题（短链、信息流、秒杀任选）。
4. 写 5 个 STAR 行为故事，并各准备 30 秒与 90 秒两个版本。
