# 01 · 作品集与简历

## 一、先有作品，再谈包装

招聘方看的是「你能不能解决问题」。作品集的最低标准：

| 项目 | 要求 | 检查方式 |
| --- | --- | --- |
| 可访问 | 有线上地址，或 10 分钟内能本地跑起来 | 请别人实际跑一次 |
| 可读 | README 讲清是什么、为什么、怎么做 | 陌生人能否复述你的方案 |
| 有测试 | 一条命令跑测试，有报告 | CI 链接或截图 |
| 有取舍 | 文档里写了「为什么不用某个方案」 | 面试时能展开讲 |
| 有差异 | 至少一处值得讲的难点 | 你能讲 3 分钟不停 |

**只放 2–3 个项目**，但每个都要能撑住 20 分钟深挖。堆 8 个半成品是负分。

## 二、项目该怎么讲：四层结构

```text
① 背景与问题（1 句）
   「自由职业者的报价单靠 Excel，容易算错且无历史记录。」

② 我的方案（2 句）
   「做了报价单工具：模板 + 行项目自动计算 + PDF 导出；
     技术栈 React + Node + PostgreSQL，部署在容器里。」

③ 难点与解决（重点，3 句）
   「难点是金额精度与并发编辑：金额改用整数分存储，
     编辑用 version 乐观锁，冲突时提示用户重新加载。」

④ 结果与反思（1 句）
   「上线后自己用了两个月，报价时间从 20 分钟降到 3 分钟；
     当时如果先做数据模型设计，能少返工两次。」
```

## 三、STAR：把经历写成可验证的条目

| 字母 | 含义 | 写错的常见表现 |
| --- | --- | --- |
| S 情境 | 背景与约束 | 「公司有个项目」（太模糊） |
| T 任务 | 你要解决什么 | 「我负责前端」（没说目标） |
| A 行动 | 你具体做了什么、为什么这么做 | 「我用 React 做了页面」（没讲判断） |
| R 结果 | 量化结果与收获 | 「项目上线了」（没有数据） |

```text
差：负责开发电商后台的订单模块，使用 React 和 Node。

好：接手订单模块时，列表接口在 1 万条数据下响应 4.2 秒（S）。
    目标是把 p95 压到 500ms 以内（T）。
    定位到 N+1 查询与缺失复合索引，改造为批量加载并新增 (user_id, created_at) 索引；
    列表增加游标分页（A）。
    最终 p95 从 4.2s 降到 280ms，错误率从 1.2% 降到 0.3%（R）。
```

**量化不了怎么办**：用「范围／频率／影响面」替代，例如「覆盖 3 个业务线、日均 5 万次调用」。但**绝不能编数字**。

## 四、简历结构（一页为佳）

| 区块 | 内容 | 篇幅 |
| --- | --- | --- |
| 抬头 | 姓名、岗位、联系方式、GitHub／作品集链接 | 1 行 |
| 技能摘要 | 3–5 行，按层次写（语言／框架／数据／工程） | 4–6 行 |
| 项目经历 | 2–3 个，每个 3–5 条 STAR 要点 | 主体 |
| 工作／实习经历 | 有则写，突出职责与结果 | 按需 |
| 教育与其他 | 学校、证书、开源贡献 | 2–3 行 |

**技能写法对比**：

```
差：熟悉 JavaScript、HTML、CSS、React、Vue、Node、MySQL、Redis、Docker、K8s、Python...

好：
- 语言与框架：TypeScript / React（熟练，可独立设计组件与状态结构）；Node.js / Express（熟练）
- 数据：PostgreSQL（索引设计与查询优化）、Redis（缓存模式与失效策略）
- 工程：Docker 多阶段构建、GitHub Actions 流水线、Vitest + Playwright 测试
```

**原则**：写「熟练度 + 证据」，不写一长串名词。

## 五、作品集入口怎么组织

```text
GitHub 主页 README（或个人站点）
├─ 项目一：一句话定位 + 线上地址 + 技术栈 + 3 个亮点 + 架构图
├─ 项目二：同上
└─ 链接到：技术笔记 / 学习日志（可选，能体现思考过程）
```

**每个项目仓库必备**：README（含截图与快速开始）、`docs/design.md`、测试命令、CI 徽章。

## 六、常见减分项

| 减分项 | 为什么减分 | 改法 |
| --- | --- | --- |
| 简历写「精通」一堆技术 | 一问细节就露馅 | 改成有证据的熟练度描述 |
| 项目只有本地能跑 | 招聘方无法验证 | 部署上线或写一键启动脚本 |
| 全是教程复刻项目 | 看不出独立设计能力 | 挑一个做二次开发并说明差异 |
| 简历超过两页 | 重点被埋没 | 压到一页，删掉无关经历 |
| 链接失效 | 显得不认真 | 提交前逐个点开验证 |
| 只列技术不写结果 | 无法判断水平 | 每条都补量化结果 |

## 七、动手练习

1. 用 STAR 重写你三个项目的经历条目，每条必须含至少一个量化结果。
2. 把你的技能栏重写为「能力 + 证据」，删掉所有没有证据的形容词。
3. 按「四层结构」写一份 3 分钟的项目口述稿，并录音听一遍。
4. 请一位同学按你的 README 跑一次项目，记录他卡住的地方并修复。
