# 全栈术语速查表

> 阅读讲义时遇到陌生词，回到这里查一句话解释。按主题分组，中英对照，便于搜文档时直接复制英文关键词。

## 1. 运行环境与工具

| 术语 | 中文 | 一句话解释 |
| --- | --- | --- |
| Shell / Terminal | 命令行终端 | 用文本命令操作系统的界面，Windows 上常用 PowerShell |
| PATH | 环境变量 PATH | 系统按它列出目录去查找可执行程序 |
| Package Manager | 包管理器 | 安装与锁定依赖版本的工具，如 npm、pnpm、yarn |
| SemVer | 语义化版本 | `主版本.次版本.修订号`，`^1.2.3` 允许次版本升级 |
| Lockfile | 锁文件 | `package-lock.json`／`pnpm-lock.yaml`，保证团队安装结果一致 |
| Monorepo | 单仓多包 | 一个仓库管理多个包／应用，共享配置与依赖 |
| CI / CD | 持续集成／持续交付 | 代码推送到远端后自动跑检查、构建与部署的流水线 |
| Artifact | 构建产物 | 构建过程输出的文件，如 `dist/`、Docker 镜像 |

## 2. 前端基础

| 术语 | 中文 | 一句话解释 |
| --- | --- | --- |
| Semantic HTML | 语义化 HTML | 用 `<nav>` `<main>` 等标签表达结构，利于无障碍与 SEO |
| Accessibility (a11y) | 无障碍 | 让键盘用户、读屏用户也能完整使用页面 |
| Flexbox | 弹性盒布局 | 一维布局模型，适合行或列方向的排列与对齐 |
| CSS Grid | 网格布局 | 二维布局模型，适合整页骨架与复杂区域划分 |
| Media Query | 媒体查询 | 按屏幕尺寸等条件切换样式，实现响应式 |
| Specificity | 选择器权重 | 决定多条规则冲突时谁生效的优先级规则 |
| Box Model | 盒模型 | 元素由 content、padding、border、margin 组成 |
| BFC | 块级格式化上下文 | 独立的布局上下文，用于清浮动与避免外边距塌陷 |

## 3. JavaScript 与 TypeScript

| 术语 | 中文 | 一句话解释 |
| --- | --- | --- |
| Primitive / Reference | 原始值／引用值 | 原始值按值传递，对象按引用传递 |
| Scope & Closure | 作用域与闭包 | 函数能记住并访问定义时的词法作用域 |
| Hoisting | 变量提升 | 声明在执行前被登记，`let/const` 存在暂时性死区 |
| this | 调用上下文 | 由调用方式决定（或箭头函数继承外层） |
| Event Loop | 事件循环 | 协调宏任务与微任务、驱动单线程异步执行的机制 |
| Microtask / Macrotask | 微任务／宏任务 | `Promise.then` 是微任务，优先于 `setTimeout` 宏任务 |
| Promise / async-await | 承诺／异步函数 | 异步结果的统一抽象与同步写法糖 |
| Prototype Chain | 原型链 | 对象属性查找沿 `__proto__` 向上回溯的机制 |
| Immutability | 不可变数据 | 不修改原对象而返回新对象，便于比较与追踪变更 |
| Generics | 泛型 | 让类型随传入参数变化的复用手段 |
| Type Narrowing | 类型收窄 | 通过判断把联合类型细化到具体分支 |
| Structural Typing | 结构类型 | TS 按形状兼容，而非按声明名字兼容 |

## 4. 前端框架与工程化

| 术语 | 中文 | 一句话解释 |
| --- | --- | --- |
| Component | 组件 | 可复用的 UI 单元，输入 props 输出界面 |
| JSX | JSX 语法 | 在 JS 中书写类 HTML 结构的语法糖 |
| Props / State | 属性／状态 | props 由外部传入且只读，state 由组件自身维护 |
| Reconciliation | 协调／Diff | 框架对比新旧虚拟树，决定最小 DOM 更新 |
| Hooks | 钩子 | 在函数组件中复用状态与副作用逻辑的 API |
| Lifting State Up | 状态提升 | 把共享状态上移到最近公共父组件 |
| SSR / SSG / CSR | 服务端渲染／静态生成／客户端渲染 | 三种页面生成与渲染时机 |
| Bundle / Tree Shaking | 打包产物／摇树优化 | 打包去除未被引用的代码以减小体积 |
| HMR | 热模块替换 | 改代码后局部刷新，保留应用状态 |
| Code Splitting | 代码分割 | 按路由或组件拆包，按需加载 |

## 5. 网络、后端与接口

| 术语 | 中文 | 一句话解释 |
| --- | --- | --- |
| HTTP Method | 请求方法 | GET/POST/PUT/PATCH/DELETE 表达操作语义 |
| Status Code | 状态码 | 2xx 成功、3xx 重定向、4xx 客户端错、5xx 服务端错 |
| Header / Cookie | 请求头／Cookie | 承载元数据与浏览器自动携带的小段状态 |
| CORS | 跨域资源共享 | 浏览器同源策略下，服务端显式授权跨域请求 |
| Middleware | 中间件 | 请求处理链上可插拔的处理单元 |
| Idempotency | 幂等 | 同一请求执行多次与执行一次效果相同 |
| REST / GraphQL | 表述性状态转移／图查询 | 两种接口风格：资源化 vs 按需取字段 |
| OpenAPI | 接口描述规范 | 用机器可读文档描述 REST 接口 |
| Pagination / Cursor | 分页／游标 | 大量数据的切片读取方式 |
| Rate Limiting | 限流 | 限制单位时间请求量，保护服务 |

## 6. 数据库与缓存

| 术语 | 中文 | 一句话解释 |
| --- | --- | --- |
| Schema | 数据库模式 | 表、字段、约束与关系的定义 |
| Primary / Foreign Key | 主键／外键 | 唯一标识行，以及指向另一张表的引用 |
| Normalization | 范式化 | 拆表减少冗余，降低更新异常 |
| Index | 索引 | 加速查询的数据结构，代价是写入变慢、占空间 |
| Transaction (ACID) | 事务 | 原子性、一致性、隔离性、持久性的操作单元 |
| N+1 Query | N+1 查询 | 循环内逐条查库导致的性能陷阱 |
| ORM | 对象关系映射 | 用代码模型操作数据库，如 Prisma |
| Migration | 迁移 | 版本化的表结构变更脚本 |
| Cache Aside | 旁路缓存 | 先查缓存，未命中回源并回填 |
| Cache Invalidation | 缓存失效 | 数据变更后让缓存同步更新的难题 |

## 7. 安全

| 术语 | 中文 | 一句话解释 |
| --- | --- | --- |
| Authentication | 认证 | 你是谁，如登录 |
| Authorization | 授权 | 你能做什么，如权限校验 |
| Hashing / Salt | 哈希／加盐 | 单向摘要存密码，加盐抵抗彩虹表 |
| JWT | JSON Web Token | 自包含的签名令牌，注意过期与撤销 |
| OAuth 2.0 / OIDC | 授权框架／身份层 | 第三方登录与访问授权的标准 |
| CSRF | 跨站请求伪造 | 借用户身份发起非预期请求，用令牌与 SameSite 防御 |
| XSS | 跨站脚本 | 注入脚本窃取数据，输出转义与 CSP 防御 |
| SQL Injection | SQL 注入 | 拼接 SQL 被注入恶意语句，用参数化查询防御 |
| OWASP Top 10 | 十大安全风险 | 业界公认的 Web 安全风险清单 |

## 8. 测试与质量

| 术语 | 中文 | 一句话解释 |
| --- | --- | --- |
| Unit Test | 单元测试 | 针对单个函数或模块的最小验证 |
| Integration Test | 集成测试 | 验证多个模块协作，如 API + 数据库 |
| E2E Test | 端到端测试 | 从界面到数据库全链路验证用户流程 |
| Mock / Stub | 模拟／桩 | 用可控替身隔离外部依赖 |
| Coverage | 覆盖率 | 被测试执行到的代码比例，不等于质量 |
| Lint / Format | 静态检查／格式化 | 自动发现坏味道与统一代码风格 |
| TDD | 测试驱动开发 | 先写失败测试，再实现使其通过 |
| Flaky Test | 抖动测试 | 结果不稳定的测试，会侵蚀团队信任 |

## 9. 系统设计与架构

| 术语 | 中文 | 一句话解释 |
| --- | --- | --- |
| Scalability | 可扩展性 | 增加资源即可提升处理能力 |
| Vertical / Horizontal Scaling | 纵向／横向扩展 | 升级单机 vs 增加机器数量 |
| Load Balancer | 负载均衡 | 将请求分发到多个后端实例 |
| Stateless | 无状态 | 实例不保存会话，便于水平扩展 |
| CAP Theorem | CAP 定理 | 一致性、可用性、分区容错三者不可同时满足 |
| Consistency | 一致性 | 强一致、最终一致等不同保证级别 |
| Message Queue | 消息队列 | 异步解耦与削峰填谷的基础设施 |
| Microservices | 微服务 | 按业务边界拆分可独立部署的服务 |
| Circuit Breaker | 熔断 | 依赖故障时快速失败，防止雪崩 |
| Observability | 可观测性 | 通过日志、指标、链路追踪理解系统状态 |
| SLA / SLO / SLI | 服务等级约定／目标／指标 | 对外承诺、内部目标与度量口径 |
| Design Pattern | 设计模式 | 可复用的解决方案模板，如工厂、策略、观察者 |
| SOLID | 面向对象五原则 | 高内聚低耦合的经典指导原则 |

## 10. 协作与交付

| 术语 | 中文 | 一句话解释 |
| --- | --- | --- |
